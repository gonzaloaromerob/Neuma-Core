# Red-team checklist para cambios de NEUMA

Antes de declarar estable una decisión o principio relevante, preguntar:

- ¿Qué evidencia podría demostrar que esta conclusión es incorrecta?
- ¿Estamos confundiendo una preferencia de diseño con un principio universal?
- ¿La recomendación depende de capacidades actuales de una herramienta que pueden cambiar?
- ¿Existe una alternativa más simple con menor costo o acoplamiento?
- ¿Qué efecto de segundo orden estamos omitiendo?
- ¿La automatización reduce realmente riesgo/trabajo o solo desplaza complejidad?
- ¿Estamos preservando agencia humana o introduciendo dependencia acrítica?
- ¿La trazabilidad permitiría reconstruir y cuestionar la decisión meses después?
- ¿El diseño sigue funcionando si cambia el proveedor o desaparece un conector?
- ¿Qué parte del argumento es evidencia y qué parte sigue siendo hipótesis?

El objetivo no es contradecir por sistema, sino encontrar fallas materiales antes de institucionalizarlas.
