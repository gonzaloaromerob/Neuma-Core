# NEUMA 3.0 — estado de preparación

Fecha de corte: 2026-08-18

## Resultado de esta fase
La fundación pública mínima está preparada como **draft**, separada del corpus interno y construida desde documentos rectores de SharePoint.

## Completado
- definición pública mínima de NEUMA 3.0;
- jerarquía de fuentes;
- mapa del corpus;
- recuperación prudente del panorama comparativo;
- hoja de ruta de propiedad intelectual, licenciamiento, marca y legado;
- cierre del PR anterior sobredimensionado sin merge;
- rama limpia desde `main` y PR específico para revisión.

## Decisiones consolidadas
1. SharePoint conserva originales y corpus interno rector.
2. GitHub conserva únicamente material deliberadamente versionable/publicable.
3. `NEUMA - Estrategia 2026` es histórico, no autoridad doctrinal; su comparación con otros marcos se rescata solo tras actualización.
4. No se publicará el Manual de Gobierno interno completo por defecto.
5. No se añadirá todavía Creative Commons a `main`.
6. CC BY-SA 4.0 es la opción base a evaluar para documentación pública, no una licencia ya concedida.
7. La marca y el derecho de autor requieren carriles jurídicos separados.
8. El MIT existente debe delimitarse frente a futura documentación CC.

## Pendientes que requieren un Gate externo o jurídico
No son pendientes metodológicos de esta fase:
- búsqueda formal de antecedentes de marca en SIPI y análisis de clases/confundibilidad;
- decisión de titularidad y estrategia marcaria;
- revisión jurídica de autoría/procedencia y asistencia de IA;
- registro de obras ante DNDA una vez aprobadas las versiones finales;
- selección/aplicación definitiva de Creative Commons;
- política de marca y reglas de uso;
- estrategia patrimonial/sucesoral del activo intelectual;
- publicación o merge a `main`.

## Criterio de salida
La fase metodológica/documental queda cerrada cuando el PR limpio está listo para revisión y los pasos jurídicos irreversibles permanecen explícitamente bloqueados hasta su Gate correspondiente.

NEUMA continúa siendo un marco vivo: una release estable representa una versión gobernada, no una declaración de perfección o cierre definitivo.
