# Checklist de revisión canónica

Antes de promover un cambio a `main`:

- [ ] El propósito del cambio es claro y acotado.
- [ ] No contiene secretos ni información cuya publicación no sea deliberada.
- [ ] Hechos, hipótesis y recomendaciones están diferenciados cuando aplica.
- [ ] El System of Record de las fuentes está respetado.
- [ ] No se copiaron evidencias internas innecesariamente.
- [ ] Los enlaces y referencias canónicas son coherentes.
- [ ] El diff completo fue revisado.
- [ ] Se consideraron efectos secundarios automáticos.
- [ ] Existe Gate C explícito si el merge representa una decisión material nueva.
- [ ] La postcondición de `main` será verificada después del merge.
